# 批量细纲生成的来源与原子提交保护

**目标：** 只有完整有效、来源未变化且仍有效执行的生成任务才能追加一次细纲；保护作者手动大纲。

**设计：** 项目行锁作为大纲变动共同锁，手动create/update/delete与worker终态共用。worker启动时事务锁项目读取项目提示字段与全部大纲快照，模型后再次锁项目比较来源，再锁job核组织/项目/类型/RUNNING/attempt；追加条目、step与job结果同事务。最终step凭证恢复ack丢失，取消/终态/旧轮次不追加，来源变化明确失败不重试。严格JSON正好请求章数，每项非空合法长度标题/摘要，不静默截断或部分采纳。记录可得模型用量。

**页面：** 列表和动作迟到响应隔离项目/卸载与请求代际，载入失败可见；生成提交先保存当前正文并核来源，项目来源的完成结果才刷新大纲，只读正文不刷新。

**取舍：** 仅任务锁不能串行化两个任务与手工编辑；项目锁与来源快照无需schema且为短事务，不在模型请求时持锁。全部大纲变化保守失效，角色/世界名称为请求快照。框架手动删除入口仍保留，但验收不删除真实/持久合成记录。
