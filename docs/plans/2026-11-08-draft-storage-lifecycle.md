# 本地草稿修订清理与容量可见性

目标：减少已处理副本与handled标记累积，不自动删除未确认稿，也不误删另一页面后写修订。仅改变本机草稿格式/清理与恢复提示，服务器正文流程不变。

原始链路：v1每writer可变key，跨页处理只能写immutable handled标记，旧正文及标记均残留。不得为节省容量用比较后删除另一页可变key。

设计：新副本v2每revision独立key；写新修订成功后仅清该页面上一独立key，写失败保留上一稿。保存确认或显式丢弃v2时删不可变修订，无永久handled。读取兼容v1，旧可变副本沿原marker处理且不冒险自动迁移/删除。统计当前账号章节可恢复副本数与估算UTF16占用；逐份丢弃后继续提示下一份，不批量删除未确认稿。无需后端/依赖/schema。

1. RED复现已处理v2预期可释放空间但旧实现残留，写入失败保留原稿、后续修订不误删；保留旧v1明确兼容夹具。
2. v2 helper与hook own写后清前稿，恢复stats/下一版，存储异常保持可见与服务器保存可用。
3. 浏览器验证确认/丢弃实际释放、双页面后写安全、旧v1兼容、统计及quota failure保留；独立复审与完整unit/e2e fake/build/typecheck/密钥排除。
4. docs current-progress/localization/onboarding/report，提交快进master同步GitHub/Gitee，独立hash/tree/clean回执外存。

边界：无TTL自动清理、无跨章节管理页、估算不代表浏览器配额；v1残留安全兼容不全量删除，写新稿需要临时空间且失败保留原稿。真实长稿输入性能单独取证。

设计复核确认：读取严格核对物理key与payload修订及范围；新稿先写入并更新ref再清理旧稿，配额失败不删前稿；清理失败保留新ref，后续服务器确认仍清正确版。统计UTF16估算含当前范围v1标记/异常记录，不宣称剩余配额。
