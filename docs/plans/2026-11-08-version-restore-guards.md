# 版本回滚正文保护实施计划

**目标：** 回滚只覆盖作者确认的同一章、同一份已保存正文，保留当前稿的版本与记忆一致性。

**证据：** 实际 PostgreSQL 回滚夹具确认，原接口会覆盖确认后其他页面保存的新稿，虽然旧实现会快照这份新稿。本轮沿用用户持续优化与双仓库同步授权，不调用外部模型。

**设计：** 复用正文保存的 SHA-256 基线与章节行锁；接口要求 chapterId/baseContentHash。锁后异稿基线冲突返回 409，不创建版本、不改正文或记忆；当前已是目标正文则无副作用返回，支持确认丢失重试。非空当前正文在同一事务中快照，变化时失效来源记忆。页面先保存并核对来源，再展示确认；确认后再次核对、保存，编辑或切章淘汰确认。列表、对比、回滚异步响应按请求代际及组件生命周期隔离。

**取舍：** 仅保留快照不能阻止过期意图；持久回滚操作凭证需要扩展 schema，本轮采用同目标正文幂等，符合现有正文保存协议。哈希不检测内容回到原样的 ABA，不实现文本自动合并。
