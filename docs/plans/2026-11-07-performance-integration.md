# 性能功能安全集成计划

目标：将性能实验分支和未提交预算功能中主分支尚缺的可用能力迁入当前 master，保留会话认证、13 类任务、中文提示、CJK token 估算、配置错误分类、人工版本证据和批量续写语义。

设计取舍：直接合并旧工作树会回退已完成能力；完整重写会丢失已有验证。采用基于当前 master 的选择性迁移，并在最终集成提交记录实验分支父历史；原实验工作树及其未提交文件保持字节不变。

## 顺序与验收

1. 独立 codex/performance-integration 工作树，冻结锁文件安装、生成客户端，复用已验证 master 基线。
2. 迁移组织/项目趋势、预算继承与设置、队列观测和恢复审计。先补异步会话、未登录、跨组织、非法预算输入回归；API 统一 await requireSession，服务查询始终带 organizationId。
3. 手工重试和过期租约恢复采用状态条件更新，恢复与审计写入同一事务；不更改当前 worker 的瞬时重试和配置错误分类。
4. 保留现有 heartbeat/schema/migration，迁移上下文预算和指纹等缺失 worker 增量；不覆盖中文 prompts、CJK 估算或当前 handlers。
5. 接入现有页面与标签，补样式和必要状态；不引入新的设计系统或依赖。
6. 全量 unit/typecheck/schema、浏览器 e2e、匿名 API 401、双组织隔离与真实数据库预算约束验收。复用现有本地库，执行迁移前先核对结构，不重置库。
7. 独立复核改动与原稿哈希，更新进度和验收报告，集成回 master 并推送 GitHub/Gitee；核对两端最终 commit/tree。

## 明确边界

保持真实模型调用关闭；用户正文、凭据、依赖和生成产物均不提交。旧实验原稿保留；已被 master 取代的实现以范围对照记录，避免把历史提交数量当新增能力。使用现有会话和数据库模式，不为本轮任务扩展产品功能。
