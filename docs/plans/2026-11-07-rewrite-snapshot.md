# 改写与润色候选的来源绑定计划

目标：候选始终属于发起时的章节、选区与原文；移动选区不改变替换位置，切章或改文不得借用旧候选。保留人工点击采纳及现有自动保存，不新增供应商调用或自动替换。

原始链路：worker只返回selectedText/newText，page完成effect读取selectionRef.current并从其取得位置；结果无chapterId或原文快照，apply只比较局部片段。同文不同位置/不同章可以误替换；handleRewrite未flush导致尚未保存的新选文在worker不存在。

方案：本地请求快照包含章节id、原始完整正文、原选区和任务id；发起前flush，await期间核对同一快照与当前章节/正文，返回后绑定准确job id。结果仅消费匹配请求，切章及时失效；采纳前完整快照一致。移动选区可以继续采纳原位置；改文/切章明确失效，取消/失败无可采纳旧结果。完整正文只留页面内存，不上传或写日志。

备选：只增加chapterId可防串章却不能防同章重复片段；自动按引用重新搜索可能选错重复文本。本轮选严格快照，宁可让作者重新发起，不猜测重定位。worker终态及usage另轮检查，不把未改的后端声称已修复。

1. 浏览器合成job回执+真实登录/章节夹具，RED复现完成前移动到同文第二处、选区外改文仍能应用、未保存文本发起请求；跨章同文为额外隔离回归。
2. 最小实现页面请求/结果快照与生命周期；回归采纳原位置一次、切章/改文拒绝、取消/丢弃保持、延迟创建回执失效。必要纯函数测试校验完整快照和请求对应。
3. 独立只读复核；完整unit、fake e2e、build、typecheck，保留RED/GREEN与环境失败证据；本轮不调用外部模型。
4. 更新progress/localization/onboarding/report；提交快进master同步GitHub/Gitee并核对hash、tree与clean状态，回执外存。

独立审查扩展：旧保存完成不能清新稿dirty；反向乱序（B先完成、A后写库）需同hook Promise队列串行保存，跳过排队中已被新稿取代的版本。新增第9项浏览器红绿证明旧HTTP挂起时新稿排队，最终真实DB保存最新稿。该队列不覆盖visibility keepalive、跨标签或服务端并发。
