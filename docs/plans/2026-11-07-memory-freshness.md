# 来源正文变更后的记忆失效

目标：已改写/删除的章节记忆不能继续污染后续上下文，保留历史可复查。

- 共享DB helper锁定租户范围章节行，失效其active来源记忆为superseded，不物理删除。
- 手动保存、DESLOP应用、版本恢复、worker finalize（生成/续写/批量）内容实际变化时同事务失效；无内容变化不失效。
- softDeleteChapter同事务失效；上下文两条查询拒绝来源已删除/越界的遗留记忆，保留无来源的项目记忆。
- 行锁与抽取保存使用相同章节行，避免并发抽取/编辑产生新旧状态错配；版本恢复使用事务内最新正文快照。
- RED/GREEN与真实DB回滚夹具覆盖变更路径、幂等保存、抽取→改写→再次抽取→下一章预览。整章新抽取和失效在一个finalize事务。
- 本轮不新增外部模型调用，不冒充作者审核现有正文；完整单测/typecheck/build/e2e及独立复核后，更新报告/进度并集成同步双远程。
