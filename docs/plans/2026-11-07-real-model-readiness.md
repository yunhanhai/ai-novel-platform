# 真实模型接入修复与验收准备

目标：用户已选择先完成接入修复与验收准备。保持现有 fake 模式，不新增真实调用，不录入、生成或修改凭据，不开启收费渠道。

方案：统一严格 64-hex 密钥解析；测试连接先验证组织归属与状态，USER_KEY 才要求加密密钥，PLATFORM_KEY 直接使用对应环境凭据。模型解析的显式档案与所有 fallback 按组织、项目和供应商状态限定，拒绝外组织/其他项目和停用供应商。提供无 HTTP、无写库的预检命令与就绪/阻断原因。

1. 用回归测试复现 PLATFORM_KEY 被主密钥误阻断、非法主密钥截断、演示测试忽略归属、显式模型档案越界和原始异常泄露；确认 RED。
2. 修复 shared/worker/web 密钥读取与 provider ping，组织档案解析；保留无档案 fallback 与配置错误立即失败契约。
3. 增加 model:preflight 只读命令：检查 web/worker 模式、凭据存在性、供应商/档案有效性，不输出密钥/密文，不联网、不写库。配置完成后明确下一步受控 ping、单章、续写/诊断验收路径。
4. 全量测试、类型、e2e；验证实际数据库跨组织模型解析，预检确认当前缺凭据。更新接入手册、进度、计划和报告。
5. 精确提交本任务，集成回 master 并同步已有 GitHub/Gitee，保存两端提交回执。原实验原稿继续保留。

就绪不等于真实验收：未取得用户供应商/模型/凭据前，报告真实调用及质量均未验证。用户以后配置 API key 后再执行真实模型测试，不用本轮模拟输出充当结果。
