# 真实模型接入与验收手册

> 面向操作者（老程）的完整路径：从零配置到全链路验收，再到评测数据积累。
> 每一步都带验证命令与预期结果。按顺序执行即可，不需要额外上下文。
>
> 适用版本：评测基座（eval:mine + pairwise judge）与错误分类均已就位的 master。

---

## 第 0 步：前置检查

确认 PostgreSQL 在跑：

```powershell
$env:PGPASSWORD='postgres'
& 'D:\myTool\develop\PostgreSQL\pgsql\bin\psql.exe' -h 127.0.0.1 -p 5432 -U postgres -d ai_novel_platform -c 'select 1;'
```

预期返回 `1`。

## 第 1 步：选择凭据模式并同步两个进程的配置

网页与后台任务服务读取不同文件：web 使用 `apps/web/.env.local`，worker 使用根 `.env`。两处 `USE_FAKE_MODEL`、数据库连接与实际使用的凭据必须一致，修改后重启 web + worker。

- 通过设置页录入 API key：保存为 USER_KEY，需要两文件配置同一个 ENCRYPTION_KEY。
- 使用已有 PLATFORM_KEY 供应商：两文件配置对应 OPENAI_API_KEY 或 ANTHROPIC_API_KEY；不需要加密主密钥。供应商 baseURL 与模型名仍从模型设置读取。

ENCRYPTION_KEY 用于加密供应商 API key（完整 64 位十六进制）。**已有密文时恢复原密钥，不要替换**。以下生成命令只适用于首次配置 USER_KEY：

```powershell
node -e "process.stdout.write(require('node:crypto').randomBytes(32).toString('hex'))"
```

把首次生成或已有原密钥写入根 `.env` 和 `apps/web/.env.local`：

```ini
USE_FAKE_MODEL="false"
ENCRYPTION_KEY="<64位十六进制>"
```

**验证**：重启 web + worker 后打开「设置 → 模型设置」，真实模式下不再显示“演示模式”。USER_KEY 录入需要有效加密密钥才能启用输入框；已有 PLATFORM_KEY 不需要该输入框。

## 第 2 步：录入供应商与模型档案

1. 「设置 → 模型设置 → 供应商」→ 新建供应商：
   - 类型选 OpenAI 兼容（DeepSeek/Kimi/通义等均兼容此协议）
   - baseURL 填供应商文档给的地址（注意是否带 `/v1`）
   - 粘贴你的 API key；设置页创建的供应商自动使用 USER_KEY，无需另选 authMode
2. 「模型档案」→ 新建档案：选刚建的供应商，填供应商支持的模型名，taskType 保持 default；必须先有档案才能真实测试连接。
3. 执行只读预检：

   ```powershell
   pnpm model:preflight
   # 仅检查目标组织，避免其他测试账号的缺配置影响判断
   pnpm model:preflight --organization-id=<组织UUID>
   # 项目预检会包含该项目和它继承的组织默认档案
   pnpm model:preflight --project-id=<项目UUID>
   # 针对一个档案查看详细配置结论
   pnpm model:preflight --profile-id=<档案UUID> --json
   ```

   退出码：0=本地配置具备候选；2=仍缺配置/处于演示模式；1=参数、文件或数据库检查失败。预检只读文件/数据库，必要时本地验证密文解密，不联网、不写库、不输出密钥或密文。Web 配置按 Next.js dev 的实际加载与变量展开规则读取，worker 按 Node --env-file 的规则读取；请优先在两处直接填写同一有效值，避免两种展开语义产生差异。ready 仅说明本地候选配置通过，不证明网络、余额、模型存在或生成质量。未指定档案时只要求至少一个候选可用，其他档案问题仍列在报告中。
4. 点**测试连接**：真实模式下对当前组织该供应商的最早模型档案发一次最多 1 输出 token 的请求。单次测试关闭 SDK 自动重试，15 秒超时后取消底层 HTTP 请求；普通生成任务的重试策略保持原样。
   - mode=real 且 ok=true：真实接口完成请求，仍需单章质量验收。
   - mode=fake：未发送真实请求，不能当接入成功。
   - 失败：按下方错误表排查；所有提示隐藏原始供应商异常。
   - 本地取消只表示停止等待并关闭连接，不能保证供应商立即停止计算或计费；1-token ping 是否兼容目标模型仍需实际验证。

**验证**：测试连接 OK + 档案列表可见。

## 第 3 步：单章冒烟验收

新建一个验收专用作品和空白首章，填写简短梗概、角色与方法论，避免覆盖已有正文。先以 fast 模式生成 1 章，再验证 balanced；初次不执行自动连更。记录 jobId、所用档案、质量模式、耗时、步骤、tokens、版本与上下文指纹。供应商可能单独重试，PerformanceBudget 是应用步骤预算，不等于供应商账单硬上限。

观察点：

| 检查项 | 预期 |
|---|---|
| 任务卡片状态 | 排队中 → 生成中 → 已完成 |
| 生成耗时 | 真实模型通常 30s~3min（比 fake 慢一个量级，属正常） |
| 正文内容 | 不再是 fake 固定文本，风格与所选方法论/风格档案相关 |
| 章末钩子 | 正文末尾应有继续阅读的牵引（rubric 的 hook 维度） |

若失败：任务卡片会显示**中文排查提示**（如"API key 无效，请到设置→模型设置检查"）——按提示修正后重试。配置类错误不会浪费重试（worker 判定不可重试时直接定稿）。

## 第 4 步：全链路验收清单

按顺序逐项验证，每项记录通过/失败与观察：

- [ ] **续写**（继续写）：正文末尾接续，语气人称一致
- [ ] **改写**：选中一段 → 改写 → 对照卡 → 应用 → 正文替换
- [ ] **润色**：同上，检查是否只修文风不改情节
- [ ] **审校**：审校 tab → 开始审校 → 检查建议的**引文是否真实存在于正文**（引证验真）→ 应用一条 → 检查采纳标记
- [ ] **自动连更**：连更 2 章 + 勾选「连更时维护记忆」→ 完成后正文变长、记忆 tab 出现新的章节摘要（accepted 状态）
- [ ] **记忆抽取**：抽取记忆 → proposed 记忆出现（角色状态类会自动淘汰旧状态）
- [ ] **版本对比**：版本 tab → 对比当前 → 差异摘要合理
- [ ] **导出**：TXT 下载正常

任何一项失败：记录任务卡片的错误提示原文（这本身就是评测素材——错误分类的实测样本）。

## 第 5 步：评测数据积累与基线

真实使用（写作、采纳、修改）会自动沉淀证据，无需任何额外操作：

| 信号 | 采集方式 |
|---|---|
| AI 版本语料 | 每次生成/续写/连更自动落版本 |
| AI 版 → 作者改版配对 | 手动保存自动快照（修改 ≥10% 且距上次 ≥10 分钟） |
| 审校采纳率 | 应用替换时自动回写 job |
| 被否定章节 | 删除章节自动入负样本 |

随时重跑基线（只读，不写任何业务数据）：

```bash
pnpm eval:mine
```

输出：`docs/eval/baseline-<日期>.md`（聚合数字，进 git）+ `.eval-out/dataset-<日期>.json`（含正文，**勿提交**）。

**首次真实基线 = 真实模型 + 若干章真实写作之后的那次重跑。** 之前的报告已诚实标注为 fake 样本。

## 第 6 步：评审层启用（可选，A/B 盲测用）

评审器（`apps/worker/src/eval/judge.ts`）已实现 pairwise + 交换检验，当前待真实模型接入。启用方式：后续会话中把评审 runner 接到已配置的 model profile 上（一次小改动），即可对两段正文跑盲评：

```
输入：版本A + 版本B
输出：winner(A/B/tie) + 逐维度判断 + 原文证据 + 是否稳定（交换检验）
```

评分质量依赖真实模型；同模型自评有偏好风险，建议评审与生成用**不同供应商**。

## 错误对照表

| 任务卡片显示 | 原因 | 处理 |
|---|---|---|
| ENCRYPTION_KEY 缺失或格式不正确 | USER_KEY 模式没有可用的 32 字节加密密钥 | 配置恰好 64 位十六进制并重启 worker；已有密文时恢复原密钥，不要随意换新 |
| 未配置 API key | USER_KEY 未录入密钥，或 PLATFORM_KEY 缺对应环境变量 | 前者在模型设置中录入供应商密钥；后者配置 OPENAI_API_KEY / ANTHROPIC_API_KEY 并重启 worker |
| 无法解密已保存的 API key | 主密钥与加密时不一致，或保存的密文已损坏 | 恢复原 ENCRYPTION_KEY，或在当前有效主密钥下重新录入供应商密钥 |
| 当前供应商类型尚不支持 | 已有档案选择了尚未实现的 adapter 类型 | 选择已支持的供应商类型，保存后测试连接 |
| 模型档案配置不完整 | 档案缺关联供应商或有效模型名 | 补全档案；与“完全没有匹配的档案（NO_MODEL_PROFILE）”区分排查 |
| API key 无效或未授权 | key 错/被吊销/供应商不匹配 | 核对 key；用测试连接验证 |
| API 余额不足 | 账户欠费 | 供应商控制台充值 |
| 模型名不存在 | 模型名拼写错 | 对照供应商文档的模型名 |
| 接口地址不可达 | baseURL 错/网络不通 | 检查协议与路径；本机网络代理 |
| 请求过于频繁被限流 | 429 | 自动重试，无需操作 |
| 模型响应超时 | 生成过长或服务慢 | 自动重试；连更时可降低章数 |
| 模型服务暂时不可用 | 5xx | 自动重试，稍后再试 |

## 回滚方案

若真实模式出现阻塞问题，同时改回根 `.env` 和 `apps/web/.env.local` 的 `USE_FAKE_MODEL="true"` 并重启 web + worker 即可回到演示模式。已生成的真实内容与版本不受影响（fake 模式只在**新任务**时生效）。

## 诊断与正文要求的补充验证（2026-11-07）

Step档案已启用低推理强度及JSON模式，真实诊断成功回执见 [后续报告](../reports/2026-11-07-diagnostic-quality-followup.md)。设置页模型档案可修改两项；只有支持的渠道才开启JSON模式，正文生成/续写仍为纯文本，旧档案默认关闭。低推理强度本身不保证快速或有正文。

AI面板“本次正文要求（可选）”可填最少/最多字数和每行一条必含片段。生成结果会显示实测字数、缺失片段和是否达标；检查通过只说明字数/精确片段满足，不证明文学或因果正确。快速模式不修订，均衡模式会在现有调用预算内把实测缺口加入一次修订；预算不足则保留正文并标未达标。

本轮诊断成功不代表均衡生成稳定：均衡另章草稿120秒未完成；快速稿567字未达目标，单独续写后826字。续写现在记录实际模型耗时，历史0值不回写。阅卷分数为模型辅助意见，风格漂移分越低越好。
## 均衡链路有限通过与增强降级（2026-11-07）

均衡生成新增一次真实四步成功样本（项目专用8192档案、800字、258秒），详见 [均衡容错报告](../reports/2026-11-07-balanced-resilience.md)。组织默认仍4096；同轮它返回过空草稿，所以本次成功不代表默认渠道稳定。不要只增加等待或自动重试来掩盖空响应。

增强步骤审校/修订/记忆抽取遇到瞬时模型错误或无效结果时，保留最后一份有效正文，任务结果会明确显示未完成项；配置类错误、数据库错误以及必需草稿失败仍失败。空白正文禁止覆盖，审校JSON不完整不代表通过。重试增强前先看已有版本，避免重复生成整章。字数/片段检查通过仍须核对人物推断及新背景来源。
